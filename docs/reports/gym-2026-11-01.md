## Found and fixed by the gym

- **DaveBridge 0.2.1:** the `where-is-machine` starter query died with StackOverflowError on the production world.
  Mod tile entities whose members can't be listed on a dedicated server get a metaclass built from a superclass;
  Groovy's MetaClassImpl handed any call on such a class object (`getName()`, `toString()`) back to the registry,
  which returned the same metaclass forever. Fixed in `SrgMetaClass.AncestorMetaClass`, with a regression test that
  fails without the fix.
- **The `lesson` tool was never wired** into the `bridge` MCP server (the two features came from different
  branches). Added `lesson` / `lesson_stop`.
- **Prompt:** Dave told a player to "tell me you opt in" for client eval; SOUL now names `/davebridge optin`.
  The planner reply linked a recipe hash as a label; the markup guide now forbids that.
- **Gym itself:** answers are matched by prompt (a background planner's late follow-up belongs to its own turn),
  tool use is counted per question, and a delegated planner's follow-up is awaited.
